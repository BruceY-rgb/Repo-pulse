# Repo-Pulse 项目计划书

## 1. 项目范围 (Project Scope)

### 项目目标

**Repo-Pulse** 是一个基于大语言模型（LLM）的 **SaaS 化研发效能与智能治理平台**。系统通过深度整合 Git 工作流，把 Git 事件转换为高价值语义信息，辅助开发者做判断与分发，并为管理者提供量化的工程质量视图。

### 核心交付产物 (In-Scope)

- **多源数据集成**：GitHub / GitLab Webhook 监听 + 标准化归一。
- **AI 智能研判**：摘要 + 风险评估（LOW / MEDIUM / HIGH / CRITICAL）+ 分类与建议。
- **过滤与审批**：INCLUDE / EXCLUDE / TAG 规则 + 编辑-审批工作流。
- **研发效能看板**：DORA 4 指标 + 风险趋势 + 团队活跃度。
- **多渠道通知**：邮件 / 钉钉 / 飞书 / 站内信。

### 项目边界 (Out-of-Scope)

- **代码托管与编辑**：不提供代码仓库托管服务或在线 IDE 功能。
- **CI / CD 执行**：不直接负责自动化构建、测试执行或生产部署。
- **桌面端**：不交付 Electron 等桌面应用。
- **第三方集成**：本学期不集成 Jira、Slack、Teams（"别人已经做得很好，不重复造轮子"）。

## 2. 过程模型 (Process Model)

### 混合模型：敏捷迭代开发 + 瀑布式文档驱动

- **敏捷开发 (Sprint)**：用于应对 AI 模型调优、Prompt 设计与前端交互迭代的不确定性，支持快速原型验证。
- **瀑布流 (Milestone)**：严格执行软工课要求的关键评审节点（第 10 / 12 / 16 周），确保文档产出与代码进度同步。
- **每轮迭代闭环**：需求细化 → 设计 → 实现 → 评审 → 回顾，每轮约 1 周，覆盖 Phase 0–5 共 8 个迭代。

### 沟通与检查机制

- **双周检制度**：每周四与周末晚上 21:40 同步进度，各负责人汇报当周完成情况和遇到的阻塞。
- **小群协作**：开发、测试、汇报建立专属讨论组，组长与产品介入所有小群以保持信息对齐。
- **协作工具**：GitHub Issues 跟踪任务、Turborepo 增量构建、Notion 文档协作。

## 3. 规模估算 (Scale Estimation)

| 维度 | 估算值 |
| :--- | :--- |
| 总代码量 (SLOC) | ≈ 6000 行（后端 3500 + 前端 2500） |
| 核心模块数 | 12 个 NestJS 功能模块 |
| 前端页面数 | 9 个主页面 + 共享组件库 |
| 数据模型数 | 10 个 Prisma Model + 11 个枚举 |
| 团队规模 | 8 人 |
| 开发周期 | 8 周 |
| 总人力投入 | 约 16 人月 |

### 复杂度热点

1. **AI 多模型抽象层**：统一封装多家 LLM 服务的差异。
2. **BullMQ 队列可靠性**：异步消费、指数退避、幂等设计。
3. **Prisma 关系建模**：多对多 / 复合索引 / 枚举落地。
4. **SSE 流式输出**：从后端 AI 模型到前端的流式渲染链路。

## 6. 任务与计划 (Tasks & Schedule)

8 周开发周期按"**先骨架、再数据、后智能、最后可视化**"的顺序推进。模块之间是顺序串联的：仓库集成依赖认证、AI 分析依赖事件、流程管理依赖 AI 结果、最后看板依赖前面所有数据积累。

| **周次** | **阶段** | **核心交付目标** | **主要负责人** | **关键里程碑** |
| :--- | :--- | :--- | :--- | :--- |
| **W1** | Phase 0 · 基础设施 | Monorepo 骨架、Docker 环境、立项书与 WBS | 朱自超 + BE | Docker Compose 一键启动 Pg + Redis |
| **W2** | Phase 1 · 认证系统 | 高保真 Demo、GitHub OAuth 登录跑通 | 杨思行 + FE + BE | DDL 4.5：完成高保真 Demo |
| **W3** | Phase 2 · 仓库集成 | Webhook 接收、BullMQ 队列配置、API 契约 | 郑启楠、金昊明 | 收到首条真实 Webhook 并入队 |
| **W4** | Phase 3 · AI 攻坚 | AI SDK 抽象层、Prompt 调优、SSE 流式 | 杨思行 + BE | 前端首次看到流式 AI 摘要 |
| **W5** | Phase 4 · 流程管理 | 过滤规则引擎、审批工作流、WebSocket 推送 | BE + FE | 审批通过后 3 秒内站内信到达 |
| **W6** | Phase 5 · 数据看板 | DORA 指标、Recharts 仪表板、报告原型 | 部淞豪、黄旭峰 | **系统封版，功能冻结** |
| **W7** | 测试与优化 | 黑盒 / 压力测试、Bug 修复、文档美化 | 袁黄烨 + 全员 | Bug 清零，文档归档 |
| **W8** | 兜底与展示 | 源码整理、演示录屏、PPT 定稿 | 张锦鹏 + 全员 | 一键跑通 + 终版展示 |

### 风险缓冲

- **W4 配救火队员**：AI 攻坚是关键节点，安排机动人力应对突发问题。
- **W6 系统封版**：硬截止，封版后只修 Bug、不加新功能。
- **W7 留作 Bug 缓冲**：整周作为测试与缺陷修复的弹性窗口。
